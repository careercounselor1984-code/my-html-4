# 초기상담 종합의견 서버 이전 1차

## 변경 범위

초기상담 Ⅰ·Ⅱ유형의 「선택 문구로 의견 초안 만들기」와 기존 의견 반영 버튼이 서버의 `journal-opinion` v1을 사용한다. 화면의 입력·직접 수정·초안 검토/추가·최종 기록 작성 흐름은 유지한다. 두 초기상담 모듈의 로컬 종합의견 생성 규칙과 미사용 Legacy 생성 함수는 제거한다.

일반 메모의 줄 정리, 전산 입력 문구 보조, IAP, 구촉수당 계산 등 다른 기능은 이번 이전 대상이 아니다. 이미 공개된 과거 버전과 수정 이력은 회수되지 않는다.

## 권한과 입력

서버는 실제 사용자 토큰을 검증하고 최신 직원 계정의 활성/퇴사/초기 비밀번호 변경 상태, 연결 직원의 활성 여부, 등록 PC 및 등록 만료를 확인한 뒤 생성한다. 브라우저 CORS나 화면 잠금만으로 권한을 결정하지 않는다.

통합본 상위 창이 인증 토큰을 전달하며 초안 화면은 토큰을 별도로 보관하지 않는다. 사용자 변경·로그아웃 이후 도착한 응답은 사용하지 않는다.

전송 항목은 생성에 필요한 16개 문구, 지원 항목 코드 배열 2개, 신체 작업조건 검토 필요 여부 boolean이다. 이름·연락처·등록번호·건강 상세 서술은 별도 필드로 전송하지 않는다. 자유기재 칸에 직접 개인정보를 적은 경우 해당 문구에는 포함될 수 있다. 서버 애플리케이션은 입력·출력을 데이터베이스에 저장하거나 로그에 남기지 않는다.

## 오류·비용

- 입력 변경, 최종 의견/초안 직접 수정, 초기화 뒤 늦게 도착한 응답은 적용하지 않는다.
- 중복 클릭을 제한하고, 실패 시 기존 작성 내용을 보존한다. 10초 응답 제한 이후 안내를 표시한다. 직접 의견 작성은 계속 가능하다.
- 서버는 입력 키·타입·길이·전체 요청 크기와 지원 코드 목록을 검사한다.
- 요청 제한은 인스턴스 내 보조 장치이며 전역 청구 한도가 아니다.
- 작업 당시 Supabase 조직의 `plan=free`, `tier=tier_free`를 확인했다. 이번 작업은 유료 전환, 결제 설정 변경, 외부 AI API 호출을 추가하지 않는다. 무료 한도를 초과하면 서비스 사용이 제한될 수 있다.
- 서버 전용 원본은 공개 GitHub 저장소에 넣지 않는다. 서버 관리 권한으로만 관리한다.

## 검증

서버 비공개 시험에서 기존 코드와 출력 1,200건이 완전히 일치했다. 토큰/계정 중지/퇴사/직원 비활성/비밀번호 변경/등록 PC/만료, 입력 스키마·크기 제한, 오류와 요청 제한을 검증했다. 실제 배포 함수도 토큰 누락·잘못된 토큰을 401로, 다른 Origin을 403으로 거부했다.

공개 테스트는 서버 결과 연결, 최소 항목 전송, 기존 의견 보존, 중복·늦은 응답·실패·로그아웃 처리를 검증한다. 생성 규칙 시험은 서버 원본과 함께 별도로 관리한다.

실제 직원 계정으로 로그인한 전체 경로 및 정상 생성의 운영 응답시간은 계정 세션 없이 검증할 수 없었다. 내부 생성 계산시간은 매우 짧지만 네트워크와 인증 조회 시간이 추가되므로 이를 실제 사용 지연으로 간주하면 안 된다. 운영 적용 후 기존 초안 버튼으로 확인할 항목이다.
