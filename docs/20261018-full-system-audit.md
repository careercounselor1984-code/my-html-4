# 통합본 전체 점검 (2026-10-18)

## 범위와 수정

28개 내장 화면과 중첩 화면을 포함한34개 문서의105개 인라인 스크립트 및 외부 JS 구문, 로컬 자산 참조를 점검했다. 기존 로그인/직원 권한, 상담 입력·종합의견, IAP 인정일수, 수당, 저장/복원, 전산 전송, 채용 보관함, 자체모집, 내담자 안내, 작업 탭·일정 연결 회귀 검사를 실행했다.

실제 오류: 다음 상담 예약 IIFE의 문자열 변수 URL이 브라우저 URL 생성자를 가려 초기화가 중단됐다. SCHEDULE_URL로 변경하고 실제 DOM 초기화·예약 테스트를 추가했다.

예약 응답 대기30초 후 무한 대기 대신 확인 안내를 제공한다. 처리 여부가 불명확한 동일 예약 재시도는 기존 requestId를 재사용해 서버 idempotency를 유지한다. 로그인 대기 중에는 타이머를 정지하고, 로그아웃·계정 변경 시 대기 요청을 정리한다. 통합본 직원 이름을 일정표에 전달해 서로 다른 계정의 우발적 예약을 방지한다. 구형 메시지와 호환성을 유지한다.

검증: 기존25개 및 예약 DOM 신규1개, 총26개 로컬 회귀 검사. 전체 Chrome 시작 시 미처리 예외, 로그인 잠금, 예약 초기화를 확인하는 검사를 CI에 추가했다. 내장 코드/로컬 자산 참조 누락은 발견하지 않았다. 새 화면/메뉴나 확장프로그램 직원 인증은 추가하지 않았다.

## 서버/운영 점검

통합본의 직원계정·등록기기·전자공문·채용보관함·IAP 관련 테이블은 RLS 활성 상태를 확인했다. 서버 코드를 브라우저에 되돌리지 않았다. 일정표 저장소의 별도 감사 문서에서 로그아웃·동기화·개인 할 일·알림·캐시 및 인쇄를 확인한다.

기존 보안 어드바이저 경고는 코드 실행 권한 자체와 데이터 노출을 구분했다. 통합본 DB의 익명 실행 가능4개 함수는 DART/Q-Net 경로이며 상담 기록 함수가 아니다. RLS 활성·정책 없음은 해당 테이블의 일반 클라이언트 직접 접근 차단 용도인 경우가 있다. 이번 점검에서 서버 정책·직원 자료·결제 설정은 변경하지 않았다.

## 확인 한계

자동 검사와 모의 계정/자료로 실제 Chrome을 검사한다. 실제 직원2명이 서로 다른 PC·휴대폰에서 동시 저장하는 상황, 고용24 실전 입력, iPhone 홈 화면 푸시 수신, 실제 프린터의 양면/배율은 실기기 검증과 구분한다. 외부 API 제공 상태와 법령/매뉴얼의 전체 최신성 재검증은 이번 기능·보안 점검에 포함하지 않는다.

추가: 오래된 1회성 유예 패치 workflow의 YAML 구문 오류를 확인해 읽기 전용 검증 작업으로 교체했다. 이미 배포된 p11의 유예 영역·스크립트만 검사하며 소스 자동 수정·커밋·쓰기 권한은 제거했다.
