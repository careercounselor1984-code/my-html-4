# 구직촉진수당 지급액 계산 서버 이전

## 범위

구촉수당 화면(p06)의 지급액 산정을 `journal-stipend` v1으로 이전했다. 2026년 기존 계산식을 그대로 분리한 작업이며 법령·금액 기준을 새로 개정한 작업이 아니다. 초기상담 종합의견 서버 기능은 유지하고, IAP·학교 IAP 날짜·기간 계산은 이번 변경에 포함하지 않았다.

서버 전용 원본은 공개 저장소에 포함하지 않는다. 과거 공개 버전의 계산식과 수정 이력은 회수되지 않는다.

## 화면·연동

- 기존 `calculate()` 진입점과 결과 생성 버튼을 유지한다. 전산 도우미가 값을 불러오면 같은 진입점으로 재계산된다.
- 입력 변경은 400ms 단위로 합치고, 동일 입력의 진행 중 요청을 공유한다. 짧은 최근 결과 캐시는 자동 표시용이며 최종 결과 생성은 최신 서버 계산을 요청한다.
- 서버 응답 대기·실패 때 이전 확정액을 새 금액처럼 표시하지 않는다. 직접 작성한 결과는 지우지 않는다.
- 늦게 온 응답, 생성 대기 중 입력 수정, 로그아웃 이후 응답은 적용하지 않는다.
- 입력이 바뀐 뒤에는 지난 금액이 들어 있는 출력의 복사를 막고 결과 재생성을 안내한다. 생성된 출력의 직접 수정은 허용한다.
- 기존 간결한 지급·소득 요약과 카카오톡 문구를 유지한다.
- 2027년 이후 기준 미검증 차단도 유지한다.

## 권한·비용·입력

초기상담 서버와 같은 직원 계정 검사(실제 토큰, 계정 활성/퇴사/비밀번호 변경, 연결 직원 활성, 등록 PC 및 만료)를 서버에서 수행한다. 기존 테이블과 정책은 변경하지 않는다.

요청은 기준연도, 지급률, 가족 수, 소득 유무와 세 종류의 소득 합계 숫자만 포함한다. 이름·등록번호·연락처·소득 내용·상담사 의견·활동 내역은 전송하지 않는다. 서버 애플리케이션은 요청·결과를 DB에 저장하거나 로그에 남기지 않는다.

Supabase 조직의 무료 요금제를 확인했고 유료 전환·결제 설정·외부 AI API를 추가하지 않았다. 무료 한도에 도달하면 사용이 제한될 수 있다. 함수 내 요청 제한은 인스턴스 내 보조 장치로 전역 청구 한도를 대신하지 않는다.

## 검증과 한계

- 비공개 서버 시험: 기존 코드와 1,209건 정확한 결과 비교. 소득 경계값·가족 수·지급률·숨겨진 기존 소득·미래 연도 포함.
- 서버 입력 타입·허용값·크기 제한과 인증 거부·요청 제한 검사.
- 실제 배포 서버의 토큰 누락/무효 401, 다른 Origin 403 확인.
- DOM 시험: 최소 숫자 항목 전송, 연속 입력 합치기, 동일 요청/짧은 캐시, 금액 표시·기록 생성, 직접 수정본 보존, 오래된 결과 복사 방지, 실패·로그아웃·재로그인·늦은 응답·미래 연도 차단 확인.
- 기존 검사를 포함한 `tests/*.test.cjs` 23개 통과.

정상 직원의 실제 로그인 세션이 없어 운영 환경의 전체 경로 및 정상 계산 응답시간은 측정하지 못했다. DOM의 서버 응답은 시험용이며 실제 금융 판단을 대체하지 않는다. 이번 작업은 기존 프로그램 결과의 동일성을 검증한 코드 이전이다.
