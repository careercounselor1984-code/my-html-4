# 통합본 복제 방지 1차 점검

점검일: 2026-10-18 (한국시간). 기준 커밋: `5726ca4`.
대상: `careercounselor1984-code/my-html-4`와 통합본이 사용하는 로그인 서버.

## 결론

통합본은 공개 저장소의 정적 HTML 안에 상담 도구 코드를 담고 있다. 로그인은 서버의 직원 계정 확인을 거치지만, 이미 공개된 화면·생성 코드를 숨기지는 못한다. 원본 비공개 관리와 주요 생성 기능의 서버 이전이 복제 저항성을 높이는 핵심이다.

이번 변경은 기존 코드의 자동 인증 생략과 오래된 배포 파일을 정리하는 제한된 1차 보완이다. 코드 복제 방지 완료로 해석하면 안 된다. 브라우저 코드 수정으로 화면 잠금을 제거하는 행위까지 막을 수 없으며, 이미 공개된 코드나 내려받은 파일도 회수되지 않는다.

## 확인한 사실

| 항목 | 코드·서버 확인 결과 | 처리 |
| --- | --- | --- |
| 저장소 공개 범위 | GitHub 메타데이터의 visibility가 public | 현재 유지. 비공개 전환은 Pages 요금제·배포 구성 확인 후 진행 |
| 상담 도구 배포 | index.html의 PAGES 배열에 초기상담, IAP, 구촉수당 등 코드가 Base64로 포함됨 | Base64는 암호화가 아님. 서버 이전 대상으로 분류 |
| 로컬 실행 인증 | bootstrap이 file:, localhost, 루프백 주소에서 인증을 생략함 | 자동 생략 삭제. 로컬 실행도 같은 로그인 절차를 사용 |
| 구버전·단독 파일 | login-test.html은 구버전 통합본 전체, p11-decoded.html은 종료·사후관리 도구 단독 코드 | 둘 다 최신 통합본 로그인으로 이동. 복구 링크의 query/hash 유지 |
| 점검 스크립트 | .github/patch_deferral.py가 p11-decoded.html을 저장소 루트에 다시 생성함 | 임시 디렉터리에만 생성하도록 변경 |
| 서버 로그인 확인 | counselor-login v6의 check_session은 토큰 검증 후 계정 active, terminated_at, 직원 active를 검사 | 확인된 기존 보호 유지. 서버 변경 없음 |
| 계정 테이블 | counselor_accounts는 RLS 활성, anon/authenticated 직접 SELECT 권한 없음 | 서버 카탈로그에서 읽기 전용 확인 |
| 공고 보관함 | counselor_job_archive는 RLS 활성, anon SELECT 불가. 정책은 계정·직원 활성, 퇴사 여부, 비밀번호 변경 여부와 소유자/공유 여부를 확인 | 기존 보호 유지 |
| 등록 PC | counselor_device_bindings는 본인 auth.uid() 및 활성 직원 조건의 RLS 사용 | 기존 보호 유지. PC 식별값은 위조 불가능한 하드웨어 인증이 아님 |

다른 Supabase 프로젝트의 일정표, 별도 서비스 전체, 확장프로그램 패키지는 이번 코드 점검 대상에 포함하지 않았다. 관련 서버에 광범위한 권한 변경을 적용하지 않았다.

## 검증

- jsdom에서 실제 통합본 인증 스크립트를 실행하여 공식 주소 및 file/localhost/루프백 등 7개 주소에서 비로그인 잠금 확인.
- SDK 누락, 네트워크 오류, 사용 중지 계정, 다른 등록 PC일 때 화면 잠금과 공고 보관함 클라이언트 접근 차단 확인.
- 초기 비밀번호 변경 요구, 활성 직원의 정상 화면 진입, 기존 heartbeat의 사용 중지 감지 확인.
- 레거시 두 경로가 비밀번호 복구 파라미터를 보존해 최신 통합본으로 이동하는지 확인.
- 실제 로그인 서버의 check_session을 토큰 없이, 잘못된 토큰으로 호출하여 두 요청 모두 401 unauthorized 확인. 직원 계정 로그인이나 비밀번호 변경은 실행하지 않음.
- 기존 회귀 검사를 포함한 `tests/*.test.cjs` 22개 통과. 문법·변경 공백 검사 통과.

DOM 기반 인증 테스트는 직원의 실제 계정 로그인, 인쇄 화면, 확장프로그램의 실제 전산망 연동을 대체하지 않는다.

## 다음 단계와 완료 조건

1. 원본 비공개 배포: GitHub 요금제와 Pages 배포 구성을 확인하고, 비공개 원본에서 필요한 공개 화면만 배포하는 구성을 만든다. 기존 직원 주소와 로그인 복구 주소, 확장프로그램 허용 주소를 먼저 검증한다. 저장소 비공개만으로 공개 페이지의 코드가 숨겨지지는 않는다.
2. 핵심 처리 서버 이전: 초기상담 문장 생성 등 한 기능을 먼저 선정한다. 입력 중 필요한 항목만 전송하고, 서버가 매 요청마다 토큰·현재 계정·재직 상태를 확인한 뒤 결과만 반환한다. 비로그인·퇴사·사용중지·비밀번호 미변경 계정의 거부 및 정상 직원 결과 일치를 검증한다. 전체 생성 코드를 로그인 후 내려주는 방식은 승인된 사용자의 코드 복제를 막지 못한다.
3. 확장프로그램: 현재 패키지를 확인한 뒤 브라우저 DOM 수집·입력은 로컬에 유지하고, 보호할 서버 처리에 같은 직원 권한 검사를 적용한다. Chrome 웹스토어의 원격 실행 코드 제한을 준수해야 한다.

이번 단계에서는 저장소 공개 범위, 서비스 주소, 데이터베이스 정책, 실제 직원 계정 및 비밀번호를 변경하지 않는다. 다음 단계는 배포 구성과 서버 계약을 준비한 뒤 별도 변경으로 진행한다.
