# IAP 전산 입력 등록번호 필수 대조 (2026-10-19)

통합본의 IAP 전송자료에는 등록번호가 없었으며, 도우미 1.4.23은 번호가 없는 전송자료를 육안 확인 대상으로 처리해 자동입력을 허용했다. 통합본 전송자료에 전체 `iapNo`를 포함하고, 도우미 1.4.24에서 번호 없는 자료를 거절한다.

## 변경

- 통합본: `A`와 10자리 이상 숫자로 구성된 전체 IAP 등록번호 필수. 작성 중인 양식의 등록번호와 검색란 번호가 다르면 전송 차단. 번호 없이 작성하는 기존 기능은 유지한다.
- 부모 브리지 및 확장 브리지: 등록번호 없는 이전 전송자료 거절.
- 확장프로그램: 실제 입력할 각 프레임과 접근 가능한 상위 문서에서 화면에 표시된 전체 등록번호를 확인한다. 번호 없음·번호 불일치·여러 번호는 차단한다. 이름, 뒷자리, 구직인증번호로 대신 확인하지 않는다.
- 두 표의 대상 프레임을 모두 사전 확인한 뒤, 확인한 `documentId`로 입력한다. 자동입력 함수 안에서도 행추가와 개별 필드 변경 전 다시 대조한다. 변경 도중 번호가 달라지면 이후 입력을 중단한다.
- 실행 시작 시 전송자료를 고정하고 저장자료 전체와 비교한다. 중복 클릭을 막고 대기자료의 최대 유효기간은 24시간으로 제한한다. 현재 전산 행의 날짜만 정정하는 별도 기능은 기존대로 유지한다.
- 최종 전산 저장·제출은 자동으로 수행하지 않는다.

## 배포 파일

`releases/work24-helper-1.4.24.zip`은 1.4.23 원본을 기준으로 만든 전체 확장프로그램 소스이며 Chrome 웹스토어 업로드용이다. `manifest.json`이 ZIP 최상위에 있다. GitHub Pages의 통합본 배포와 별개로 확장프로그램은 새 ZIP을 웹스토어에 등록·게시해야 설치 사용자에게 업데이트된다. 이 변경에서 웹스토어 게시를 수행하지 않았다.

## 검증 및 제한

`tests/iap-registration-guard.test.cjs`가 실제 배포 ZIP을 읽어 통합본 전송과 도우미 검증 코드를 테스트한다. 미입력·잘못된 번호·마스킹·여러 번호·다른 참여자·서로 다른 프레임·자료 교체·일치 전송 및 프레임 문서 고정을 검사한다. 전산 입력 성공 경로의 Chrome API와 Dataset 응답은 모의 응답이다. 실제 Work24 운영 세션에서 최종 저장을 실행하는 시험은 수행하지 않았다. 전산 화면 구조가 바뀌어 전체 번호를 확정하지 못하면 자동입력이 차단된다.

입력은 전산의 여러 비동기 화면 조작이므로 전체 원자적 처리는 보장할 수 없다. 중간 실패 시 이미 입력된 정상 대상자의 미저장 행이 남을 수 있다. 다른 사람의 행을 되돌리는 위험을 피하기 위해 번호 변경 후 자동 삭제·원복하지 않는다. 전산 저장 전 표시 내용을 직접 검토해야 한다.

## 구직인증번호 연동 확인

도우미 `basic_content.js`는 `jobCertNo`, `jobCertExpire`를 추출하고 `basic.js`는 기본정보 전송자료에 포함한다. 통합본의 현재 `applyBasic`은 초기상담 날짜와 인정통지일만 반영한다. 일정표 `clients.js`의 저장·가져오기에는 구직인증번호·만료일 필드가 없다. 따라서 **수집 및 통합본으로 전달은 구현되어 있지만 일정표 저장·만료일 일정 연동은 미구현**이다. 이 수정은 해당 연동을 새로 활성화하지 않는다.

## 원본 보존

수정 전 통합본 HTML과 확장프로그램 1.4.23 전체를 별도로 보관한 후 변경했다. 기존 내담자·상담일지·일정 데이터 삭제나 데이터베이스 변경은 없다. 구직인증번호를 공개 소스 또는 배포 파일에 담지 않았다.
