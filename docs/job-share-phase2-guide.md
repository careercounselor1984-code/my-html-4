# 상담사 공유 채용공고 · 2차 개발 사용 및 검증 기준

## 실제 업무 흐름
1. `채용정보&알선 → 내 보관함`에서 공고를 등록하고 상담사에게 공유합니다. 내 보관함 기본 조회값은 **오늘**입니다.
2. `상담사 공유` 탭의 카드 화면에서 공고의 **정보제공 / 알선 / 취업** 중 진행한 작업을 선택합니다.
3. **내담자 고유번호**(상담사 간 동일하게 사용하는 내부 식별번호)를 입력하고 표시명, 실제 활동일, 간단 메모를 저장합니다. 주민등록번호, 휴대전화번호를 고유번호로 사용하지 않습니다.
4. 같은 공고의 같은 내담자는 하단의 **내담자별 진행 상태**에 한 줄로 묶이고, 다음 단계 버튼으로 후속 기록을 연결합니다. 정보제공·알선·취업은 각각 한 번만 등록됩니다. 중복 단계는 서버에서도 거절합니다.
5. 상단 통계에서 오늘/최근 7일/이번 달/전체/특정일을 선택합니다. 활동 내역은 45초 단위 자동 새로고침됩니다. 상담사별·날짜별·월별·센터별 표와 CSV를 이용할 수 있습니다.

## 개인정보/권한
- 활동 이력 상세정보(내담자 표시명, 고유번호, 메모)는 **같은 센터의 활성 상담사**에게만 공개합니다.
- 다른 센터 활동은 **건수만** 집계 RPC로 보여줍니다. 내담자나 상담사 이름은 제공하지 않습니다.
- 취소는 작성한 상담사 본인만 수행할 수 있으며 취소 기록은 보관됩니다. 로그아웃 시 화면의 데이터는 비웁니다.
- 취업 건수는 상담사 수동 등록에 따른 **운영 관리 집계**로, 고용24 공식 인정·실적 지표와 구분합니다.

## 점검 체크리스트 (실제 테스트 계정 2개 필요)
- [ ] 서로 다른 상담사 계정으로 같은 센터에서 공고 카드 및 내담자 진행 이력 공유 확인
- [ ] 같은 공고·고유번호·활동단계 중복 등록 → 서버 UNIQUE 오류 및 UI 안내 확인
- [ ] 같은 내담자의 정보제공 → 알선 → 취업 단계 연결, 취소 후 다시 등록 가능 여부 확인
- [ ] 다른 센터 사용자로 접근했을 때 내담자 상세정보가 표시되지 않는지 확인
- [ ] 다른 센터는 센터별 집계 숫자만 표시되는지 확인
- [ ] 오늘/최근 7일/이번 달/날짜 지정 집계 및 CSV 계산값 대조
- [ ] 다른 상담사 등록 후 45초 이내 카드 및 상단 합계 자동 반영 확인
- [ ] 공고 공유 해제 후에도 과거 활동 통계에 기록이 유지되는지 확인
- [ ] 로그아웃 후 개인정보 초기화 및 로그인 전 접근 차단 확인

## 현재 확인 범위
GitHub JavaScript 구문, Supabase 마이그레이션 성공, RLS/권한/인덱스 조회까지만 자동 확인하였습니다. 로그인 후 두 사용자 간 실제 브라우저·데이터 저장·동시성·반응형 레이아웃의 전체 통합 테스트는 아직 완료되지 않았습니다.

## 운영 상한
브라우저 화면은 공유 공고 최대 1,000행과 센터 내 상세 활동 최대 5,000행을 불러옵니다. 이를 초과하면 상담사·일별 세부 통계가 일부만 보일 수 있으므로 후속 서버 집계 또는 페이지네이션 확장이 필요합니다. 센터별 숫자는 별도 DB 집계 함수를 사용합니다.
